# F2H 贸合 P0.1 交互原型交付与验收清单

## 目标

以冻结业务架构 V0.8 演示从采购需求 → 供给资源 → AI候选 → 人工核验 → 双向意愿 → 引荐及协作的流程；演示内容必须显著注明虚构。

## 本轮明确实现

| 模块 | 演示验收 |
|---|---|
| 经营总览 | 虚构指标、漏斗、动态、商机入口 |
| 商机雷达 | 5条虚构需求，行业/目标市场/全文搜索 |
| 供应链 | 6条匿名虚构供方样本 |
| 匹配实验 | 规则匹配：行业硬约束、市场覆盖、标签与证据缺口解释 |
| 商机卡 | 推荐原因、规格需求、未核实项、下一步、候选 |
| 授权工作流 | 人工审核状态 → 模拟双方同意；未授权不能披露 |
| 商务协作 | 受控状态机看板（模拟记录） |
| 经营分析 | 虚构漏斗与JSON演示数据导出 |
| 基础安全 | 防止用户输入HTML注入，禁索引，适配移动端 |

## 不声称实现

真实模型API、用户登录、真实企业和海外买方验证、任何合法信保/合规认证、真实采购意愿、自动联系、交易支付、后台存储、真实权限/RLS、项目交付。

## 质量门禁

1. Node测试通过、静态构建通过；
2. 浏览器桌面与手机端可以访问及操作导航、筛选、商机卡和模拟撮合；
3. 无模拟数据冒充真实案例；
4. Vercel独立项目，不覆盖其他现有站点；
5. 子域名绑定状态及DNS需求按实际验证结果回报。

## 下一阶段不是“直接接真实客户”

T0.2技术架构冻结 → 真实身份与租户权限 → 数据授权与审核API → 可追溯证据 → 受控LLM撮合 → 安全回归 → 真实生态灯塔。
